# 2026-11-19｜手动拖拽卡顿与方向一致性

时间为 2026-11-19（北京时间）。用户反馈面部手动拖拽会卡顿、抽动，同一抓取点换方向后行程明显不同。此次先处理全脸拖拽，暂停下眼睑翻折原型。在面部的解剖约束上，用户希望固定原始外缘，并减弱眼角、嘴角的响应。本轮无新增截图。

## 排查结果

- 原内区保护每帧按输入方向检验完整三角形的投影面积。某片三角形在压缩方向提前触发，会缩小整笔位移。反方向若拉开该三角形，就能移动得更远。触发时逐帧二分求解，同一帧最多构建 14 次候选顶点并多次扫描三角形。
- 手动拖拽此前也使用器械和膨胀、挤压的通用眼口曲线权重。整条眼缝和嘴缝附近最低约 70%，眼角还乘一个最低 30% 的系数，叠加后约 21%。嘴角此前只有整条嘴缝的通用减权。
- 手动拖拽每帧将网格写回手势起始姿态加本次位移，期间表情、留置器械等写入的变化可能被覆盖。场景的随机抽搐默认关闭，故不能把用户反馈归因于随机抽搐开关。
- 三层联动的原路径每次复制多组顶点和轮廓数组，首次遇到不同拓扑还会逐点搜索反向 UV。器械脚本即使空闲也遍历全网格，并反复求纵深方向。这些属于拖拽的 CPU 负担，与解剖权重无关。

## 修复与取舍

- 在手势开始时缓存笔刷权重和普通内区的共同位移上限。通过三角形投影面积对共同拖拽向量的线性关系计算保守上限，所有方向使用同一个值。接近上限时连续减速，每帧构建一次候选顶点。普通抓取配置上限为 0.32 倍半径，几何允许距离更短时使用更短的值。切口附近沿用 0.6 倍半径的三维上限，与原来的切口翻面路径兼容。
- 首次只取最严方向的测试验证了方向一致，但细三角形压力用例的行程仅 0.0130 个局部单位。将衰减距离改为直线距离也只得到 0.0111，并可能改变原切口手感。最终沿用原切口内的网格距离，只在按下时修正受影响的细长三角形内部权重突变，同时保护锚点及切口隔离。压力用例的行程提高到 0.0393，八方向一致。
- 手动拖拽的解剖减幅集中在两眼眼角和嘴角。曲线端点局部系数约 30%，在约四分之一特征宽度内平滑回到 100%。眼缝和嘴缝中央只按笔刷响应。通用眼口减幅继续供器械、膨胀和挤压使用。
- 每帧只应用这笔手动拖拽新增的位移。鼠标位置没有变化时跳过该帧更新。取消时只扣除这笔拖拽自己的位移。下眼睑专用原型默认暂停，便于调试全脸拖拽。
- 三层联动复用顶点缓冲，使用已缓存的变换矩阵，并在反向重绑时优先匹配完全相同的 UV。无留置、缝合及剥离位移时跳过器械约束求解。维持原联动力学。

## 仍影响实际拖拽的因素

| 因素 | 作用 |
| --- | --- |
| 笔刷半径和距离衰减 | 越远响应越小，半径一半处的基础权重为 50% |
| 切口隔离 | 影响沿完整网格传播，切开的对侧可能不动 |
| 原始外轮廓及支撑顶点 | 原始外缘的位置固定 |
| 眼角、嘴角 | 局部柔性减权，端点仍可移动 |
| 单次行程与细三角形 | 普通区按共同安全上限减速，真实切口附近的行程上限不同 |
| 纵深与相邻层联动 | 纵深影响折叠层显示，层间绑定、局部剥离改变脂肪或肌肉的跟随幅度 |
| 已处于活动状态的表情、留置器械或缝线 | 独立改变网格姿态，可能影响看到的最终位移 |

## 验证

- 独立 Unity 2022.3.8f1c1 编译及 D3D11 回归通过。开发中处理了数组限定名编译错误和旧验证夹具在重建网格后复用权重缓存的问题，最终重新运行通过。
- 64×64 网格的切口压力用例验证八个方向行程均为 0.0393 个局部单位，并保持完整三角形朝向。在真实切口判定范围外的正常抓取点，向上和向下各得到 0.1688 个局部单位。以上数字来自测试网格及指定笔刷半径。
- 验证眼角、嘴角非零减幅，眼口中央无通用减幅，切口隔离、外缘固定、叠加外部姿态及取消恢复。透明切割、原有正背面 GPU 回归、三层联动、器械和单面板检查通过。
- 未在当前 Facetest 交互窗口进行帧时间或手感实测，因此没有用隔离测试推断游戏帧率。源码和验证保留于本地工作区。

## 2026-11-19｜苹果肌抓取一致性与权重热图

用户反馈同一位置有时轻松、有时很难拖，苹果肌最明显，鼻尖通常顺手。用户还希望能够一键显示全脸拖拽权重，以蓝色表示低权重、红色表示高权重。本次延续普通拖拽稳定性修复。本轮没有新增截图。

### 排查与尝试

上一轮统一了同一笔拖拽的各方向上限。每次重新按下时，笔刷网格距离和三角形限位仍根据当下的变形网格计算。局部压缩会改变下一笔的权重和限位。重叠时，原抓取还会选择第一个投影覆盖鼠标的三角形，顺序来自数组。

用保存的 Facetest 皮肤贴图和 4736 顶点的烘焙网格做隔离对照。让同一个材质位置在中性网格和人工局部压缩的网格上重新抓取。旧逻辑的两处苹果肌位移上限分别从 0.0037 降到 0.0024，从 0.0093 降到 0.0048。鼻尖对照的未压缩上限约 0.2390。其受压试验用于检查同材质点稳定性，不能当作用户自然拖动的鼻尖表现。

先改用原始网格计算。两处苹果肌的上限在不同姿态下相同，仍只有 0.0037 和 0.0093。这说明还需处理细面片压低整笔上限的问题。将残余面片强制合并成同权区域的试验会波及抓取点，已撤回。最终在局部平缓高梯度，普通完整三角形继续参与朝向约束，切缝边缘极细的裁切面片允许像自由切口边缘一样翻动。

### 当前行为

- 按下时用相机射线命中所选组织最靠前的可见三角形。用该位置对应的原始材质坐标计算笔刷范围、切口隔离和普通拖拽限位。同一材质点在被压缩或拉伸后，获得相同的基础权重。
- 笔刷半径按材质平面的直线距离平滑衰减，网格路径用于决定能否到达某个顶点。沿切口切开的对侧保持隔离。对权重突变做局部平滑，避免极细切口面片锁住整笔。这些计算在按下时完成。
- 在「操作工具」选择「手动拖拽」，点击「显示拖拽权重」或按 F8 开关。松手时显示全脸部位权重，按住时显示当前笔划实际使用的顶点权重，面板单独显示本次位移上限。蓝色 0，红色 1。描绘直接使用正反面的顶点颜色，跟随网格，保留透明切口和原深度条件。

### 验证

- **Unity 编译与自动测试**通过。覆盖同一脸颊材质点在网格压缩前后权重及上限一致、切口对侧隔离、正常区域方向一致、外缘与眼口响应、取消恢复、多层联动及器械。
- **保存网格对照**中，刷子半径为 0.75，两处苹果肌和鼻尖在原始及受压姿态下的位移上限均为 0.2400。抓取点附近的权重分别约 0.994、0.989、0.992。结果来自加载保存数据的独立测试，包含人工压缩样本。
- **D3D11 像素回读**确认权重 0 显示蓝色，权重 1 显示红色，透明切口继续显示背景色。自动验证还核对了开关、左右面材质、拖动中与松手时的显示值。
- **当前 Facetest 交互窗口**尚未实际操作。已核对保存资产和隔离渲染，当前角色表情下的实际操作手感及帧时间待复测。

隔离验证报告位于项目临时目录的 `FacetestMaterialProbe.txt` 和 `ManualDragMaterialValidation.txt`。本轮未创建 Git 提交。

## 2026-11-19｜眼睑切口粘连

20:12（北京时间）收到一张眼部拖拽特写。切口已经打开，一侧仍出现连接上下睑缘的狭长皮肤条。该图用来定位眼角内侧的局部粘连。已查本机对话与附件记录，未找到可嵌入飞书的原图文件。

从 Facetest 读取 4736 个顶点的已保存皮肤网格。两条眼部切口均无跨中心线的网格边，脂肪与肌肉使用同一份三层切口拓扑。复现时发现拖拽将切口视为遮挡线，用抓取点到顶点的直线决定是否清零。弯曲眼睑的同侧连续网格会被这条规则截断，极短边的两端可能一个运动、一个静止。反过来，有些对侧睑缘会得到接近 1 的权重。两种不连续都能拉出截图中细条状的外观。

手动拖拽现在从已应用的眼部切口判定上下两侧。位于所抓取一侧的睑缘使用连续的径向权重，对侧中段隔离。靠近切口两端时，对侧响应平滑过渡到原有弱眼角权重，切口外连续的皮肤可以一起动。第一版按最近一条眼部切口处理，随后改为对笔刷覆盖的两条眼部切口都计算，覆盖最大笔刷半径。继续使用网格可达性，并保留其他切口的隔离。旧的烘焙场景直接生效。

- **Unity 编译和自动回归**通过。新增窄弯眼缝场景，分别验证上拉与下拉时对侧中段不动、眼角非零跟随、短边没有突跳。最大半径同时覆盖双眼时也能隔离两侧。苹果肌和鼻尖的 0.12 行程、权重热图、切割、外缘与组织联动回归通过。
- **保存网格对照**覆盖左右眼、上下两侧、五个沿弧线位置和三种距睑缘偏移，共 60 组。测试范围内最坏的相邻顶点相对位移，从原边长约 3386 倍降至 1.60 倍。该比值用于识别极细网格边被拉成长条，数据见隔离报告 `FacetestEyeSeamProbe-before.txt` 和 `FacetestEyeSeamProbe.txt`。
- **GPU 回归**通过，背面、透明切口和下眼睑翻面测试仍能显示预期结果。用户当前 Scene/Game 窗口尚未手动复测。
