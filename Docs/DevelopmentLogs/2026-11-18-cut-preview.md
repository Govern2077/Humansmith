# 2026-11-18｜透明切割预览与松手网格结算

日期：2026-11-18，北京时间。独立切割交互开发进程；本轮未提交或推送 Git。

飞书日志：[透明切割预览与松手网格结算](https://bcn1apni241o.feishu.cn/docx/W339dPhrwoSP6wx52ASc1GjjnAd)。

## 用户反馈与最终目标

用户先提出将切割改为实时结算，并询问性能影响。在初步实现与测量过程中，用户明确调整方案：切割时先展示透明切割线，不切割网格，直到玩家松手才开始切割网格。最终实现以这条最新要求为准。本轮没有新增图片素材，反馈依据为本轮用户原文。

## 尝试、测量与设计变更

1. 原流程为青色 LineRenderer 画线，松手后统一切割。检查发现，物理切割不仅重建网格，还会触发相邻软组织层重新绑定。
2. 初次尝试按时间间隔增量提交新线段。合成测试：1024×1024 不透明贴图、64×64 网格、皮肤与一条相邻脂肪绑定，显式回调模拟运行时重绑；一次松手结算约 327.00 ms；8 批增量结算总计 3002.21 ms，平均 375.28 ms／批，最大 390.47 ms。因此，仅降低调用频率仍会在每批产生明显停顿。
3. 尝试缓存相同材质 UV 的绑定，平均降至 106.00 ms／批，但仍不适合高频物理结算。该版本仅为本轮中间尝试；用户改变方案后，已撤回本轮临时增量提交、专用调度、跨已切开缝隙拾取和层间绑定优化，最终 `SoftTissueLayerCoupler2D.cs` 与本轮开始时一致。
4. 首轮新增验证脚本误用了不存在的可见性 API 名称，改为实际 `IsVisibleMaterialAtCurrentPoint` 后继续验证；最终透明预览验证由 Unity 编译并通过。

上面的实时物理切割性能数据和下面的最终预览测试设置不同，不用于计算直接速度提升倍数。

## 最终实现

- **按住左键划动**：将新增路径段栅格化到临时遮罩。正反面材质的 `_CutMask` 暂时绑定该遮罩，路径内透明显示，可看到下层；不是不透明的彩色覆盖线。不改正式切口 Alpha、三角形、顶点、机械屏障或组织绑定，因此鼠标仍能在预览路径上继续采样。
- **性能路径**：首次预览复制一次正式遮罩，之后只计算新增线段和受影响像素矩形，复用临时纹理及整图缓存，不反复栅格化整条历史路径。沿用现有着色器的遮罩采样，没有增加每片元的额外纹理采样。
- **松开左键**：补采样末端，结束临时遮罩，按完整路径提交正式切割。普通开口切割只执行一次物理网格重建；闭合切割继续创建可移动碎片并保留接缝处理。
- **Esc／取消按钮／切换工具／禁用操作脚本**：取消本次临时预览，不产生新切口；已有正式切口保留。下一笔从正式遮罩开始，不带入上一笔取消的透明线。
- **操作目标**：沿用笔划开始时选定的组织层，透明预览不会在同一笔中意外切到下层。
- 面板提示同步改为「按住左键显示透明切割线，松手后切开网格；Esc 取消预览」。此前手动拖拽回退及用户已有场景设置不变。

## 最终验证

- **Unity 编译**：独立 Unity 2022.3.8f1c1 批处理编译通过运行脚本及新增 `CutPreviewValidation`。
- **新增自动测试**：透明遮罩像素、正反面材质绑定；划线中顶点／三角形／正式遮罩逐项不变、没有生成机械切口、继续拾取正常；取消／换工具／禁用后恢复正式遮罩；下一笔无残影；已有切口保留；开口松手只重建一次；闭合区域松手后分离，全部通过。
- **回归测试**：手动拖拽宽缓衰减、眼角非零弱响应及切口自由度；三层双向联动、100 帧无漂移、取消恢复、剥离、不同网格、切口重建、器械、单面板和外轮廓回归通过。
- **最终 CPU 测量**：1024×1024 合成贴图、64×64 网格，64 次预览更新合计 10.76 ms，平均 0.17 ms，最大 8.21 ms（包含首次分配／初始化）；短开口路径松手结算 103.85 ms。本组没有层间重绑，不包含 GPU、真实场景渲染及当前 Facetest；不能当作完整游戏帧率保证。松手后的正式切割仍为同步计算，仍可能短暂停顿。
- **当前 Unity 场景视觉复测**：未操作用户当前 Facetest 窗口。透明痕迹的场景观感、抖色效果下的辨识度及真实帧时间待复测；不将材质绑定检查表述为已经完成场景截图确认。
