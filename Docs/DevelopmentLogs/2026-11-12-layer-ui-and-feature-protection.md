## 1. 多层 UI 与输入修复

- 排查发现 Facetest 的皮肤、肌肉操作组件同时启用，每个 OnGUI 都向同一个屏幕矩形绘制完整工具面板；输入也可能同时被两层处理。
- 现在只选一个 PanelOwner 绘制工具面板，优先选择带眼口曲线配置的皮肤组件。
- 同一面板内提供皮肤／肌肉操作层按钮。只有 SelectedLayer 处理鼠标操作；切层时取消旧层未完成操作，留置器械按既有规则保留。
- 工具按钮设置 30 像素高度，说明与状态启用自动换行；面板按可用屏幕高度布局，长内容在同一个滚动区中显示。
- 骨骼备用面板及命中排除使用相同边栏高度，避免点击面板时开始切割。

## 2. 眼睑、唇缘与角点保护

- 使用现有 FacialFeaturePrecut2D 编辑曲线定位左右眼睑和唇缘，不依赖屏幕坐标或新的硬编码五官位置。
- 在眼口曲线附近限制手动操作的累计三维位移，越靠近眼角、嘴角限制越强；向外平滑放宽，其他组织和普通切口保留活动空间。
- 眼睑中心最大手动位移约为眼裂宽度的 12%，唇缘中心约为口裂宽度的 15%；角点更小。粗网格上的实际边界顶点会按离曲线／角点的距离过渡。
- 该上限跨多次拖拽累积，避免松手再拖时重新获得位移额度。
- 拖拽、膨胀、挤压、回弹、取消和器械约束统一走 SetToolVertices；表情／骨骼驱动继续走 SetLogicalVertices，正常张嘴、眨眼和姿态不会被强制拉回中性脸。
- 曲线组件直接向皮肤、脂肪和肌肉注册保护配置；重建网格或更换静止形状后重新计算。
- 器械求解器用实际受限后的位移记录上帧贡献，确保达到保护上限后拆线、移除牵开器仍能恢复。

## 5. 修复拖动皮肤时脂肪、肌肉不跟随

日期：2026-11-12，北京时间。

- 用户反馈：拖动皮肤时，下面脂肪层和肌肉层不再一起移动，要求修复。
- 根因：原 SoftTissueLayerCoupler2D 只有肌肉 → 脂肪 → 皮肤的向外驱动，没有从皮肤向内传递手动操作的路径。修复多层重叠 UI 后，鼠标只操作选中层，暴露了之前多层同时接收输入掩盖的问题。此前单面板测试未覆盖皮肤向内带动，现已补回归。
- 修复：新增 SetManualVertices 手动操作入口；拖拽、膨胀、挤压、取消、回弹及器械约束统一由该入口提交。普通表情和骨骼驱动继续使用原来的向外传递。
- 每次手动位移沿启用的相邻软组织链接双向传递，各层最多处理一次。先按原始 UV 绑定映射世界空间位移，再转换到各自局部坐标，保留层间深度与不同网格分辨率的适配。
- 批量提交期间暂时屏蔽普通向外回调，并刷新其已应用偏移缓存，避免反向带动肌肉后又向外叠加一次，或下一次表情更新出现跳变、持续漂移。
- 局部剥离权重同时影响向内和向外传递；已经解除连接的区域仍允许单独移动。禁用的链接与独立脱离碎片不纳入传递。接收层继续保留原始外轮廓锚定。
- 编译：运行脚本独立编译通过。
- Unity 验证：在独立后台工程一次通过皮肤 → 脂肪 → 肌肉、肌肉 → 脂肪 → 皮肤、从中层同时带动两侧、三层世界位移对齐和层间距保持、100 帧无二次叠加／漂移、回弹／取消恢复、局部剥离阻断、禁用链接、不同网格分辨率和真实物理切口重建后的传递。
- 眼口 70% 拉伸响应、单 UI 归属、原始皮肤外轮廓和全部器械回归亦通过。没有恢复多层同时监听鼠标的旧行为。
- 本轮为文字反馈，无新增用户截图；未控制当前用户窗口，当前 Facetest 的实际视觉拖拽复测未执行；未提交 Git。

## 6. 当前四层关系与版本归档

用户要求说明器械操作和骨骼、肌肉、脂肪、皮肤之间的实现关系，本次将说明一并归档。

- 四层均有独立对象；UI 当前只列出启用的操作控制器。脂肪控制器在 Facetest 中为禁用状态，因此没有脂肪按钮，但脂肪网格、切口及联动仍存在。
- 下颌骨通过轮廓附着点、区域权重和嘴唇／嘴角修正驱动肌肉。当前颅骨是独立骨骼操作目标，没有同等完整的全脸软组织附着绑定。
- 普通骨骼／表情驱动为下颌骨 → 肌肉 → 脂肪 → 皮肤；手动操作为皮肤、脂肪、肌肉之间沿相邻链接双向传递，止于肌肉，不反向拖动骨骼。
- 层间通过原始材质 UV 对应：布局相同直接对应顶点，不同布局用邻近 UV 加权；用世界空间位移适配层间变换与深度。
- 剥离降低局部软组织链接权重；现有肌肉层剥离不会自动解除骨骼附着。缝合是距离约束，尚不焊接切口网格。
- 组织切割按鼠标处最外侧完整层选择皮肤 → 脂肪 → 肌肉；操作层选择不等于切刀无条件穿透外层。
- 当前属于游戏化图像网格与位置约束系统，尚未建立各层材料模型、真实体积守恒或完整组织碰撞系统。
