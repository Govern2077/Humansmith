# 2026-11-19｜拖拽纵深与正背面重叠渲染

## 用户反馈与素材

用户反馈：拖拽后同一皮肤表面出现三层重叠（两层正面、一层背面），当前背面覆盖了应当可见的正面。建议拖拽时增加少量世界 Y 轴纵深位移，并明确要求保留靠近开口时能够翻皮的功能。

原始反馈截图已从可访问的本机原对话记录恢复：`Docs/DevelopmentLogs/2026-11-19-drag-overlap-feedback.png`，203×114；用于记录重叠时背面错误显露的实际效果，本文末嵌入原图。本轮未改动用户已有的 Facetest 场景设置。

## 排查与技术取舍

- Facetest 皮肤物体与相机均绕 X 旋转 90°，皮肤在局部 XY 平面建网格；局部 -Z 对应世界 +Y。因此，纵深处理使用局部 Z 并根据相机方向决定正负，在当前场景中就是用户提出的世界 Y 轴移动。
- 正反面是位置重合、绕序相反的两个子网格，正面先提交、背面后提交。原着色器开启深度写入，但使用 `ZTest LEqual`；当折叠分支深度相等时，后绘制的背面仍能通过深度测试。
- 原手动拖拽只改变平面位置，折叠的不同分支可能停在同一深度。只修绘制顺序不足以建立真实空间层次，因此同时加入轻微几何抬升，并处理相等深度的覆盖。

## 当前实现

1. **手动拖拽增加纵深**：抬升量为平面拖动长度的 12%，上限 0.08 个局部单位，再乘同一径向／眼角／一般特征权重与本次安全缩放。受力强的部分较靠近相机，远处平滑回落，让折叠分支分开。每次从手势起始顶点计算，保持拖动时不会逐帧累加。
2. **正确处理场景朝向**：开始手势时使用相机方向与皮肤局部法线计算抬升符号；当前场景沿世界 +Y 抬向相机，反向观察时也能换向。原始外轮廓锚点保持三维位置，取消与回弹沿原软组织手动传递路径恢复。
3. **等深度时保留正面**：主渲染深度测试从 `LEqual` 改为严格 `Less`。正面已写入的等深度像素不会被随后提交的背面覆盖。深度确实更近的背面仍然能显示；真实翻面处未被正面遮挡时也继续显示背面。
4. **保留开口翻皮**：没有恢复之前按用户要求撤回的切口防翻折／防压扁限制。开口附近仍允许三角形翻转；没有关闭背面绘制或把所有正面强制覆盖到所有背面上。
5. 保留原有透明切口 Alpha 裁剪、深度写入、阴影裁剪、皱纹采样、眼角非零弱权重与宽缓衰减。透明预览和松手网格切割的流程不变。

## 2026-11-19｜继续完善：开口最大拉伸减半与距离驱动翻卷

日期：2026-11-19，北京时间。用户要求开口最大拉伸阈值减至当前一半，同时越靠近切口越容易外翻。本次延续本篇拖拽与翻皮进程；没有新增用户图片，素材沿用前文原始截图。

### 实现与取舍

- 开口手动拖拽单次上限从作用半径的 1.2 倍改为 0.6 倍。最终三维位移统一限幅，包含平面拖动、基础纵深与局部翻卷，不能用额外翻卷绕过新上限；眼口一般减幅保留。器械继续使用各自原有阈值，本轮不修改器械逻辑。
- 从真实物理切口边缘建立每个材质顶点的距离和当前朝向，排除原始矩形外缘。抓取点和顶点各自离切口越近，翻卷响应越强；默认作用带宽 0.22 本地单位，并受刷子半径约束，最大角度默认 150°。
- 非常靠近切口的一小段皮肤近似一起旋转，之后向远处平滑衰减，避免仅鼓包而不真正翻面。绕切口旁的局部支撑位置旋转穿过切口方向的拉动，同时向相机方向抬起；沿切口滑动的翻卷较弱。
- 原有 12%／0.08 的设置继续控制基础纵深，新增加的弯曲由最终三维总位移上限约束。零拖动不卷起，保持不逐帧累积，取消与回弹沿原三层手动传递路径恢复。
- 未恢复此前撤回的切口防翻折／防压扁检查。保留普通区域朝向保护、外缘锚点、眼角非零弱权重、宽缓衰减、严格深度测试及透明切割预览；用户已有场景设置未覆盖。

技术取舍：单纯把平面距离减半会使翻面变难，因此增加的是靠近切口时的局部旋转，而不是额外拉长组织。距离与朝向只在开始手势时准备，绘制帧不重复搜索切口边缘。

### 验证结果

- **Unity 编译**：独立 Unity 2022.3.8f1c1 编译通过。
- **真实切口阈值对比**：在 0.05 至 0.60、步长 0.05 的输入范围内，贴近切口抓取在输入 0.25 时首次出现翻转三角形；较远抓取及禁用翻卷的对照在该测试范围内未翻面。该数值来自测试夹具，不能代替当前用户场景的视觉判断。
- **几何验证**：三维位移始终不超过 0.6 倍刷子半径；零输入、保持不漂移、外轮廓固定、取消恢复通过，切口处仍可真正翻面。
- **GPU 回归**：RTX 5070 Ti／D3D11 三层正背面遮挡、确实更近的背面、独立翻面与透明切口测试通过。
- **其他回归**：透明预览和松手切割、宽缓拖拽、眼角响应、三层联动、100 帧无漂移、取消恢复、剥离、不同网格、物理切口、器械与单面板通过。
- **当前 Facetest 视觉复测**：未操作用户当前窗口，实际翻卷幅度和手感仍待复测。

验证报告：`IncisionCurlValidation.txt` 与 `DragDepthRenderingValidation.txt`。本轮未创建 Git 提交或推送。

## 2026-11-19｜下眼睑定向翻折原型

用户希望下眼睑向下拉时主要表现为睑缘外翻，并能为不同切口设置不同的触发阈值。本次先试做眼部，沿用前文截图记录的翻皮背景。用户本轮没有新增图片。

- 手动拖拽以真实眼部切口为准。开始操作时，将抓取点映射回原始贴图，匹配左右眼已烘焙或已切开的路径，再区分睑缘上下两侧。只有下睑侧进入专用响应，沿切口滑动和向上拉仍使用普通拖拽。
- 向下拉时，下睑绕靠脸颊的支撑带旋转，平移随手势方向逐步减弱。翻折随拖动距离连续增加，靠近支撑带和眼角时幅度逐渐减弱。生效时保留开口处 0.6 倍作用半径的三维位移上限。
- 左右眼默认在睑缘的触发距离分别为 0.035 和 0.055 个局部单位。两个值独立显示在 FacialFeaturePrecut2D 的 Lower Eyelid Drag 设置中。距离睑缘越远，触发所需的下拉越长。超出下睑作用范围时使用普通拖拽。

本次把翻折限定在已配置眼部切口的下睑侧与向下手势。相较于前一次按一般切口距离自动翻卷，此次用眼部路径和方向共同控制触发条件。阈值和支撑带宽度是原型的初始设置。

- Unity 2022.3.8f1c1 编译及自动验证通过。测试烘焙后的左右眼能够独立触发，下睑贴边比稍远处先触发，上睑、无切口眼部、无关切口和横向手势不会触发原型。上睑在下拉测试中保持原位，取消后恢复基线。
- 独立 D3D11 测试的下眼睑有 26 个三角形翻转，项目着色器读回 1190 个可见背面像素，拖动前为 0。切口透明预览、正背面遮挡、原有手动拖拽、眼口响应、多层联动、外轮廓及器械回归通过。
- 检查了 Facetest 保存的双眼曲线及烘焙路径的对应关系，当前用户窗口中的面部观感和实际手感仍待复测。没有创建 Git 提交。
